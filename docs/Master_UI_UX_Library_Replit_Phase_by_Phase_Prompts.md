# 0. WHAT THIS PROJECT ACTUALLY IS

This project is **not the frontend of one future application**.

It is a **personal Master UI/UX Style Library** from which future applications will borrow their visual language.

The user should be able to open the library, choose:

- a component
- a visual style
- an interaction style
- a motion language
- lighting
- sound
- optional haptic behavior
- intensity
- accessibility behavior
- performance tier

and then see a live, interactive implementation.

Every catalog entry must also expose:

1. **Live Preview**
2. **All important interaction states**
3. **Responsive preview**
4. **Visual specification**
5. **Motion specification**
6. **Sound specification**
7. **Haptic specification where applicable**
8. **Accessibility behavior**
9. **Performance tier**
10. **Dependencies**
11. **Source/inspiration/license metadata**
12. **Production-ready code**
13. **Copy-code action**
14. **AI/Vibe-Coder implementation prompt**
15. **Tokens/recipe**
16. **Favorite / collection**
17. **Compare**

The library should eventually contain **50+ meaningful variations for every major component/category**, not 50 color swaps.

---

# 1. NON-NEGOTIABLE PRODUCT PRINCIPLES

## 1.1 The library must be reusable across unrelated apps

Do not couple the catalog to one future product.

A login selected today must be reusable in:

- a SaaS application
- an educational app
- an AI tool
- a scientific application
- a dashboard
- a creative application
- a mobile-first product

## 1.2 Separate behavior from appearance

A button's behavior should not be rewritten for every visual style.

Use:

```text
Component behavior
        +
Visual recipe
        +
Motion recipe
        +
Feedback recipe
```

## 1.3 Do not create 50 duplicated components

Create a composable system where many styles can share primitives while producing genuinely different experiences.

## 1.4 Premium does not mean maximum effects

Avoid:

- unnecessary glow
- excessive blur
- excessive particles
- constant animation
- sound on every action
- long artificial delays

Every effect must have a purpose.

## 1.5 Sound is part of the experience, not decoration

Use sound only where it improves:

- confirmation
- orientation
- state recognition
- atmosphere
- delight

All sound must be optional.

## 1.6 Accessibility and performance are first-class

Every major style must have:

- reduced-motion behavior
- reduced-effects behavior
- sound-off behavior
- keyboard behavior
- visible focus
- semantic states
- low-performance fallback

This makes it appropriate for selected stateful animation assets, while ordinary CSS/Motion should remain the default for lightweight UI motion.

## Master UI/UX Style Library
